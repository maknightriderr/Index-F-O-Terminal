# Automatic post-trade AI review

The Paper Trades page displays saved reviews and repeated observations. No review button, browser visit or manual retry starts the work. A supervised server observer discovers closed `TRADE_SETUP` records every minute, with a two-minute settlement delay. Winners, losers and expired exits are all eligible for investigation.

Activation is persisted per `AUTO-REVIEW-1.0`. Initial scope is the preceding seven days; subsequent closes include older positional trades. Existing AI provider settings are reused. `AUTO_TRADE_REVIEW=off` pauses discovery/processing without changing trades or deleting work. With no AI provider configured, discovered work remains pending. At most two jobs run per tick, serially. Provider/parse/evidence failures retry with exponential backoff capped at one day, indefinitely. Process crashes recover through a ten-minute database lease. Completion is fenced by lease owner and input fingerprint. Corrected or reopened trades invalidate stale reviews automatically.

Migration 046 creates only research tables and is ensured at boot. Source trades, decisions, quotes, trading rules and learning records are never updated by this feature. The report GET only reads saved data; it never calls a model or enqueues work.

Evidence includes allowlisted contract/version fields, original-risk gross/net R with recorded estimated costs, linked entry-decision fields, and sampled execution-observation MFE/MAE where available. Arbitrary reasoning, credentials and environment variables are not sent. Missing geometry, missing costs, lost tracking or voided results never receive invented net P&L. Sparse samples cannot prove that an unobserved level never traded. Source snapshots may be incomplete: the feature does not reconstruct or certify every strategy rule, IV change, underlying price path or causal explanation.

Models return schema-validated JSON and cite known fact IDs. Interpretations and proposed experiments remain hypotheses; they never modify rules, execute trades, promote strategies or automatically train the learning system. Repeated-pattern counts come from deterministic observations, grouped by strategy, source/logic version, exchange and mode. Positive and negative net outcomes are compared within each observed group. Groups overlap and cannot be summed as portfolio P&L. Previously reviewed peer results are an incomplete subset, not matched controls or proof of an edge.

Operational status is visible at authenticated `GET /api/ai-assistant/trade-reviews`: queue/retry/completion counts, the latest 100 jobs and up to 100 repeated groups. Provider errors are stored only as generic retry notices. Completion stores provider/model provenance. The existing lint/import boundary is extended to the interpreter and store without permitting trading, risk or learning imports.


AI quota protection: automatic research reviews use at most 20 model attempts per IST day by default (`AUTO_TRADE_REVIEW_DAILY_LIMIT`, 1–1000). This is an application budget, not the provider's quota/reset schedule. Failed attempts count; unused budget is not spent on empty queues. Redis preserves the daily count across restarts. Remaining reviews stay queued and resume automatically the next day. Other AI features share model cooldowns: HTTP 429 honours Retry-After or Gemini RetryInfo; an explicit daily quota without a reset hint is probed hourly. In-memory model cooldowns reset on server restart, but the durable research budget does not. Quota increases, billing changes and new provider credentials are not automatic.
