# Trading desk UI — 25 October 2026

Implements the approved graphite/teal desktop concept and a corresponding light theme, based on main `02946c1da2ec0702d89bcf7320857699e9680b03` (includes the order-flow feed alert fix).

## Delivered

- Market ticker strip and feed-health summary; timestamp/session status remains visible. Full feed details open System Health.
- Searchable chart watchlist, dominant candlestick chart with recorded volume, instrument/timeframe/spot-futures controls, selected-instrument setup spotlight, OB1/OF1 research links and compact paper-trade ledger.
- Paper-trade tabs and expandable rows retain stop, target, costs, tracking health, timestamps and explanations. Net R is read from the existing response; a missing open mark is not substituted with historical closed-trade R.
- Teal dark and light surfaces, persistent Dark / Light / System control, chart theme updates when the OS preference changes, responsive horizontal watchlist/ticker on phones, existing navigation and dynamic asset tabs retained.
- Fixed an existing UI parser that labelled routed OB1/OF1 lifecycle records as S1. Their actual family now selects the proper recorded stage and label. This changes their **displayed** eligibility where S1 and OB1/OF1 stages differ; it does not change backend eligibility.

Backend strategy, risk, position sizing, exits, database schema and API contracts are unchanged. No new scan or trade write is triggered by opening or navigating the desk. Global surface tokens also refresh other terminal screens.

## Intentional differences from the illustrative mockup

Real records determine the displayed content. There are no invented sparklines, order-block zones, CE/PE labels, research sample counts, performance totals or dates. The chart only draws overlays exposed by the existing adapter; unavailable OB/OF geometry remains explicitly unavailable. A record's underlying and option-premium levels are labelled separately; planned R:R is gross, and unknown costs remain missing. The ledger shows authoritative net R rather than inventing rupee P&L without a known position size.

All original pages remain reachable. Regime analysis and secondary market panels remain below the trading desk. On narrower desktops the watchlist moves above the chart; on phones the layout stacks and horizontal content scrolls within its panel.

## Repeat browser QA

Install Playwright in your development tooling and its Chromium binary, then:

```sh
npm run build --workspace=@fno/web
npm run start --workspace=@fno/web
# In a second terminal, from the repository root:
node scripts/ui/trading-desk-browser.cjs
```

The script requires `playwright` and the repo's existing `axe-core` to be resolvable. Optional environment variables: `DESK_QA_URL` (local server URL), `DESK_QA_OUTPUT` (screenshots), `DESK_CHROMIUM_EXECUTABLE`, `DESK_CHROMIUM_MODULE` (optional Sparticuz Chromium module for its launch args). No browser/testing dependency was added to the deployed app.
